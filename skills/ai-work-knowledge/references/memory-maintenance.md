# 维护积累的记忆与经验库

触发：笔记、经验、规则或偏好积累后要审查、去重、纠正或精简；新结果与已有条目冲突。

原始记录（对话、日志、原件）是证据，只追加不改写；维护对象是从中派生的摘要、经验、规则和流程。先查清哪些条目会进入使用者上下文：常驻、按需检索还是从不读取。常驻且错误的条目代价最高，先审。

逐条记录内容、来源位置、适用范围、支持证据、最近核实时间和状态，缺失写“未知”。状态分开：已证失效、可能过时、冲突待定、近期未用、当前有效、证据不足。旧、没被用、写得短都不等于失效；新、更具体也不等于正确。

动作只做局部增量：保留、精简、合并、取代、降级/归档、待人决定。合并时保留各自的条件和例外；取代要有新证据，新旧条目互相指向；降级或归档后仍能检索和恢复。不整库重写，不对摘要再摘要，每压缩一轮都会丢掉适用条件。绝对化规则先查是否只来自一次事故，补上范围，或降为个案记录。

默认先交只读报告：原文、建议动作、理由、证据、风险，按收益和证据强度排序，冲突与证据不足的条目单列待决。获得授权后再改：先留可恢复版本，改动最小，原始证据不动，记录改了什么、为什么改，最后复查链接和引用。维护过程产生的报告与运行日志不放进被检索的记忆库，否则会被当成证据再次引用。

首轮清理后转为局部维护：用户纠正、决定变化、问题解决、新条目与旧条目冲突或重复时，只审受影响的条目及其下游；再低频抽查常用但久未核实的条目。效果看三件事：能否检索到正确条目、同类错误是否减少、常驻上下文是否变小且没引入新错误。文件变短不算效果。没有基线先记基线。

反例：按“很久没更新且没人引用”自动降权，会误伤仍然有效的长期约束；按长度截掉尾部，丢的往往是最新事实；新旧两条冲突就默认新的胜出，会把一次误判固化下来。

依据：[增量维护与上下文坍缩](https://arxiv.org/abs/2510.04618)。论文结果来自其基准任务，不保证一般收益。
