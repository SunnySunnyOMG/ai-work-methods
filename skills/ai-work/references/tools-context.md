# 工具、上下文与专业执行

读本文件的条件：结果依赖工具或专业能力，而当前缺口妨碍实际执行。

先检查能力缺口：缺事实就取得必要来源；缺操作入口就使用已连接工具；结果返回但未影响决策则检查读取链路。上下文采用充分的最小集合，保留来源、约束和反例；不以最短为目标。

工具契约写明用途、输入、输出、错误与操作影响。反复出现的缺口才值得构建新工具；工具选择和使用经验可以放 reference。用真实任务检查工具返回是否被读取并用于结果。

专业执行以当前环境 available skills 为准。例如文档交付可用现有文档 Skill，网页探索可用当前浏览器工具。实际读过并适用才调用；没有对应 Skill 时按授权执行等效步骤并说明能力缺口，不杜撰成功调用。方法包不要求特定插件、数据库或模型品牌。

反例：接口列在文档里不等于当前工具可调用；调用成功不等于返回进入上下文；生成文件不等于目标应用可读。

依据：[工具设计](https://www.anthropic.com/engineering/writing-tools-for-agents)、[上下文工程](https://www.anthropic.com/engineering/effective-context-engineering-for-ai-agents)。
