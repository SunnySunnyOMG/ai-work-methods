# 验证器也需要验证

触发：自动检查与用户目标不一致，验证可能漏检，或产出规模超过人工验收能力。

将完成条件映射到实际证据：结构由程序检查，语义使用明确 rubric 和原材料，体验或价值取舍保留给人。让已知好结果通过、故意坏结果失败；确认检查实际运行、未因错误参数/过滤/跳过变成空测；工具传输成功仍需检查内部错误状态和实际产物。语义审阅抽查普通、边界、对抗案例，并以少量人工校准判断标准。

引用 ID 存在还需支持主张；“全年可终止”与“仅续约日前30日”冲突时回原文改结论。两个模型同意仍可能共用错误前提。交接给人时附原始证据、未决问题和选项，避免要求重做全部机器检查。

反例：exit 0且CSV仅表头，不算500条可导入记录交付。测试通过只支持所测范围；格式校验不证明 Skill 被选中、reference 被读取或判断正确。

修复验证器后重新运行，可证明当前目标的对应层，但不得回写旧检查为通过。若修改验收目标或范围，单独记录，不能据新标准宣称原目标已满足。

依据：[Agent evals](https://www.anthropic.com/engineering/demystifying-evals-for-ai-agents)、[评测最佳实践](https://developers.openai.com/api/docs/guides/evaluation-best-practices)。
