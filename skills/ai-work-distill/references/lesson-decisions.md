# 是否值得保留为新方法

触发：从结果/失败记录提炼下一次行动。

先区分用户意图、执行选择、真实结果和后来纠正。助手说完成但缺证据，保留未证；多个记录同一事件不算独立复现。项目限制不是通用方法，个人偏好标适用人群。

写一条条件动作验证：例如“跨应用交付 → 在接收方读回 → 确认所需内容可用”。回看正常与反例；稳定运行不证明理解正确，例外可以缩小规则。

检查已有流程是否已有这一决策。缺项优先补现有主干或reference；仅新增具体参数时保存项目资料；与旧规则冲突时修正或撤回；没有实质新决策时不建Skill。

反例：一次改端口解决问题只能支持该环境排查记录，不能推出所有AI任务先改端口。三次读回失败可支持交付检查条件，但不意味着所有单步任务都要重型验收。

下次实际使用后比较结果与负担；没被调用的总结不证明复用。允许保留证据、缩小范围、合并或删除规则。
