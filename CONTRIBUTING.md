# Contributing

A useful contribution makes a decision clearer or a result more reliable. Prefer a small change with a concrete condition, action, and check over a large list of project-specific instructions.

1. Describe the task, expected result, observed behavior, and skill version. Remove private data and replace it with a minimal reproducible example.
2. Show an ordinary case and a boundary or counterexample. Explain why an existing rule or reference cannot already handle them.
3. Keep the core focused. Put conditional detail in a directly linked reference; add a script only for deterministic work with a clear input/output contract.
4. Check affected local links and run the relevant repository checks. Report what was actually tested and retain any unresolved limitations.

Changes to routing should include cases that should and should not invoke the module. Changes to helpers should include a positive case and a deliberate failure. Do not add private conversations, credentials, personal paths, account identifiers, or historical tool transcripts. Do not assert broad gains from a few favorable examples.

Open an issue for a proposed method or submit a focused pull request. Contributions are under this repository's MIT license.
